# Static site generation (SSG)
SSG prerenders every static route at build time into HTML files under `dist/`. One `vite build` produces crawlable pages, assets, `sitemap.xml`, and `robots.txt`.
<DocsSection id="vite" title="Vite plugin">
  ```ts
  // vite.config.ts
  import { defineConfig } from "vite"
  import kiru from "vite-plugin-kiru"

  export default defineConfig({
    plugins: [kiru({ router: { ssg: true } })],
  })
  ```
</DocsSection>

<DocsSection id="html-shell" title="index.html">
  ```html
  <!doctype html>
  <html lang="{{kiru_locale}}">
    <head>
      <meta charset="UTF-8" />
      <meta name="viewport" content="width=device-width, initial-scale=1.0" />
      {{kiru_head}}
    </head>
    <body>
      <div id="app">{{kiru_body}}</div>
      <script type="module" src="/src/main.tsx"></script>
    </body>
  </html>
  ```

  Built HTML replaces `{{kiru_head}}`, `{{kiru_body}}`, and `{{kiru_locale}}` per route (and per locale when i18n is configured). Route `head.jsonLd` becomes `<script type="application/ld+json">` in the prerendered file — inspect any built `.html` in `dist/` to verify.
</DocsSection>

<DocsSection id="routes" title="Route tree">
  Mark the static subtree with `static: true` on the scope (or individual pages):

  ```ts
  export const routes = defineRouteTree((r) =>
    r.scope({
      static: true,
      head: { description: "My static site." },
      layout: () => import("./pages/layout.tsx"),
      notFound: () => import("./pages/not-found.tsx"),
      children: [
        r.page("/", {
          component: () => import("./pages/index.tsx"),
          head: { title: "Home", jsonLd: { "@type": "WebPage", name: "Home" } },
        }),
        r.page("/posts/[slug]", {
          component: () => import("./pages/post.tsx"),
          head: { title: "Post {slug}" },
        }),
      ],
    })
  )
  ```

  Export `i18n` from `routes.ts` when the client bootstrap needs the same config as prerender.
</DocsSection>

<DocsSection id="static-params" title="generateStaticParams">
  Dynamic segments need explicit param lists at build time:

  ```ts
  import type { GenerateStaticParamsContext } from "kiru/router"

  export function generateStaticParams(_ctx: GenerateStaticParamsContext) {
    return [{ slug: "one" }, { slug: "two" }]
  }
  ```

  **Nested routes:** child `generateStaticParams` receives parent params. For `/posts/[slug]/comments/[id]`:

  ```ts
  // pages/post.tsx — parent segment
  export function generateStaticParams() {
    return [{ slug: "one" }, { slug: "two" }]
  }

  // pages/comment.tsx — nested segment
  import type { GenerateStaticParamsContext } from "kiru/router"

  export function generateStaticParams({ params }: GenerateStaticParamsContext) {
    return [{ id: `${params.slug}-c1` }, { id: `${params.slug}-c2` }]
  }
  ```

  Build output includes `/posts/one`, `/posts/one/comments/one-c1`, `/posts/two/comments/two-c2`, and so on.
</DocsSection>

<DocsSection id="bootstrap" title="Client bootstrap">
  ```tsx
  // src/main.tsx
  import { createRouterApp } from "kiru/router/ssg"
  import i18n from "./i18n.js"
  import { routes } from "./routes"

  createRouterApp({
    routes,
    i18n,
    container: document.getElementById("app")!,
  })
  ```

  `createRouterApp` hydrates prerendered HTML and enables client navigations. Pass the same `i18n` config you use during prerender when locale URL prefixes are enabled.
</DocsSection>

<DocsSection id="loaders" title="staticLoader">
  Use `staticLoader` for data fixed at **build time**. Prerender embeds `k-page-data` in each HTML file; the client bundle reads the same payloads from `__kiruStaticLoaderPayload` on that page module during SPA navigations. Details: [Loaders — staticLoader](/v2/docs/router/loaders#staticLoader).
</DocsSection>

<DocsSection id="site-config" title="site.config.ts">
  ```ts
  import { defineSiteConfig } from "kiru/router"

  export const site = defineSiteConfig({
    url: "https://example.com",
    locales: { default: "en", prefixes: ["en", "fr"] },
    sitemap: true,
    robots: true,
  })
  ```

  All prerendered paths are written to `sitemap.xml` automatically. With `locales`, each public path is expanded per prefix (e.g. `/about` and `/fr/about`).
</DocsSection>
