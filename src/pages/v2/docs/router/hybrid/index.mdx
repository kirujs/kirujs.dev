# Hybrid (SSG + SSR)

Hybrid apps prerender selected routes at build time and server-render everything else on demand. Enable both `router.ssg: true` and `router.serverEntry` in the Vite plugin.

<DocsSection id="vite" title="Vite configuration">
  ```ts
  kiru({
    router: {
      serverEntry: "./src/server.ts",
      ssg: true,
    },
  })
  ```

  See also [SSR setup](/v2/docs/router/ssr#vite) for the server entry and HTML shell.
</DocsSection>

<DocsSection id="static-routes" title="Which routes are static?">
  Set `static: true` on the route (or an ancestor scope):

  ```ts
  r.page("/docs", {
    static: true,
    component: () => import("./pages/docs.tsx"),
    head: { title: "Docs (static)" },
  })
  ```

  Build output includes `docs.html` (and locale variants like `fr/docs.html` when i18n is enabled). The page can still use `useRequestContext()` on SSR **when** the request is handled dynamically in dev; in production, static HTML is served from disk first when `prerenderedHtmlDir` is configured on the handler.
</DocsSection>

<DocsSection id="runtime" title="Production vs development">
  | Environment | Static `static: true` routes | Dynamic routes |
  |-------------|------------------------------|----------------|
  | **Development** | Always SSR (live reload, no stale disk HTML) | SSR |
  | **Production** | Prebuilt HTML from `dist/client` when available | SSR via `createKiruHandler` |
  | **`vite preview`** | Static files only | **Not** a substitute for SSR — dynamic paths will not run the server |

  Pass `prerenderedHtmlDir` from your adapter's resolved client directory into `createKiruHandler` / `createRenderer` so production checks disk before rendering.

  Never serve raw `index.html` with unreplaced `{{kiru_body}}` for every URL — use the Kiru handler or prebuilt per-route HTML files.
</DocsSection>

<DocsSection id="sitemap" title="Sitemaps in hybrid apps">
  `defineSiteConfig` includes:

  - All prerendered static paths
  - Param-less SSR routes when `serverEntry` is set
  - Dynamic paths listed in `sitemap.include`, expanded via `generateSitemapParams` on the page module

  ```ts
  import { defineSiteConfig } from "kiru/router"

  export const site = defineSiteConfig({
    url: "https://example.com",
    sitemap: {
      include: ["/users/[id]"],
      exclude: ["/admin", "/debug"],
    },
    robots: true,
  })
  ```

  Dynamic paths in `include` need `generateSitemapParams` on the page module. Static prerender paths are included automatically.
</DocsSection>

<DocsSection id="head" title="Head and SEO">
  Static pages get full `{{kiru_head}}` in prerendered HTML. Dynamic SSR pages get per-request head. Page `defineHeadContent` and route `head` use the same merge rules in both cases — see [Head & SEO](/v2/docs/router/head-seo).
</DocsSection>
